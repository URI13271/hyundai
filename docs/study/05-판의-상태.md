# 판의 상태

`Game` 하나가 브라우저 하나의 판이다. 화면 이름은 `@screen`이다. 나머지 인스턴스 변수는 그 화면이 그리려는 값이다.

| 변수 | 뜻 |
| --- | --- |
| `@screen` | 지금 그릴 화면 |
| `@mic` | `nil`이면 아직 모름, `true`면 허용됨, `false`면 거절 |
| `@joined` | 참여 좌석 id 배열 |
| `@deck` | 이 판의 질문. 시작 때 한 번 섞는다 |
| `@index` | 지금 질문 번호. 0부터 |
| `@picks` | 좌석 id => `:a` 또는 `:b` |
| `@fresh` | 방금 말한 좌석. 한 번 그리면 비운다 |
| `@log` | 끝난 장의 집계 |
| `@leave` | 나가기 확인 창 |
| `@notice` | 좌석 화면의 오류 문장 |

`attr_reader`가 있는 것만 템플릿이 직접 읽는다. `@fresh`는 템플릿이 직접 읽지 않는다. `consume_fresh`로만 꺼낸다.

## 화면이 바뀌는 길

```text
splash --enter--> home --start--> shuffle --ready--> seats --begin--> read
                     ^                |
                     |                +-- mic 거절 시 mic --open--> shuffle
                     |
read --ready--> answer --hear--> answer
                  |  ^
                  |  +-- replay -- read
                  |
                  +-- next, 장 남음 --> read
                  +-- next, 마지막 --> done --again--> shuffle
                                         +-- home --> home
```

가드가 있어서 순서를 건너뛰는 POST는 무시된다. 좌석 화면이 아닌데 `begin_round`가 오면 `return unless @screen == :seats`에서 끝난다. 그래서 주소만 안다고 판이 깨지지 않는다.

## 섞기는 시작 때 한 번

```ruby
def start_shuffle
  @deck = Deck.deal
  @index = 0
  @joined = Seat.row.map(&:id)
  @screen = :shuffle
end
```

`Deck.deal`은 `all.shuffle`이다. 홈 미리보기는 섞지 않는다. `Deck.sample`은 `all.first`라서 항상 여행 카드다. 홈 문장을 바꾸려면 배열의 첫 장을 바꾸거나 `sample`을 바꿔야 한다. 맨 뒤에 카드를 더한다고 홈이 바뀌지 않는다.

`again`도 `start_shuffle`을 탄다. 새 순서로 다시 섞인다.

## 차례

```ruby
def current_id
  @joined.find { |id| @picks[id].nil? }
end
```

참여 좌석 중 아직 고르지 않은 첫 id다. 순서는 `Seat.row`다. 운전석, 조수석, 뒷좌석 왼쪽, 뒷좌석 오른쪽.

`hear`는 그 id에만 선택을 넣는다. 다른 좌석을 지정하는 파라미터는 없다. 한 화면이 네 자리를 대신 누르는 구조라서 그렇다.

`next_step`은 남은 참여 좌석을 기다리지 않는다. 지금까지의 집계를 `@log`에 넣고 다음 장으로 간다. 마지막 장이면 `:done`이다.

## 목소리 확인은 상태 하나가 아니다

`hear`는 선택을 저장하고 `@fresh`에 좌석 id를 넣는다. 화면 이름은 그대로 `:answer`다.

그다음 GET에서 `View#render`가 `consume_fresh`를 부른다. `@fresh`는 `nil`이 되고, 이번 렌더만 “말하는 중”을 안다. 버튼을 `locked?`로 막는다.

```ruby
def locked? = @game.screen == :read || @fresh
```

이 잠금은 그 응답 한 장에만 있다. 서버는 900ms 뒤에 풀라고 재우지 않는다. `public/app.js`가 `[data-settle]`을 보면 `POST /settle`을 보낸다. `/settle`은 상태를 바꾸지 않는다. 다만 다시 그릴 때는 `@fresh`가 이미 비어 있으므로 잠금이 풀린다.

스크립트가 없으면 새로고침으로 같은 일이 일어난다. 잠금은 서버 타이머가 아니다.

## 나가기 창

`ask_leave`는 화면을 바꾸지 않고 `@leave = true`만 한다. 템플릿 맨 아래가 `leave?`이면 같은 화면 위에 모달을 얹는다. `stay`는 플래그만 끈다. `quit`은 판을 비우고 홈으로 간다.

자동 이동은 모달이 있으면 돌지 않는다. `app.js`가 `[role="dialog"]`를 보면 `data-auto`를 무시한다. 섞는 중에 뒤로를 눌러도 1.4초 뒤 좌석으로 넘어가지 않게 하려는 것이다.

## 집계

한 장이 끝날 때 `snapshot`이 태그, 질문, A/B 문장, 표 수를 해시로 남긴다. `tally`는 그 로그에서 A가 이긴 장 수와 B가 이긴 장 수를 센다. 비긴 장은 둘 다에 들어가지 않는다.

`score_line`은 그 두 수를 문장으로 만든다. 문장 조립은 `Game`이 아니라 `View`다. 화면 문구는 뷰에 둔다.

## 화면을 하나 더 넣는다면

예를 들어 결과 앞에 확인 화면 `:check`를 넣는다면 고칠 곳은 네 군데다.

1. `Game`에 그 화면으로 바꾸는 메서드. 가드 포함.
2. `SCREEN_PATH`에 주소. 기존 주소와 겹치면 `read`/`answer`처럼 이름으로 구분한다.
3. `route`의 `when`. 메서드와 주소 쌍.
4. `screen.erb`의 `when`.

이 중 하나만 빠지면 증상이 다르다.

- 1이 없으면 버튼이 아무 일도 안 한다.
- 2가 없으면 `fetch`가 예외를 내고 500이 난다.
- 3이 없으면 폼이 현재 화면으로 되돌아온다.
- 4가 없으면 빈 화면이 나간다. `case`에 없는 이름은 조용히 아무것도 출력하지 않는다.

추가하기 전에 이 네 줄을 종이 위에 적고 시작하는 편이 빠르다.
