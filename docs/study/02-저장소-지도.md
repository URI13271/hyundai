# 저장소 지도

루트는 `lib/drive_talk.rb`의 `ROOT`다. `bin/`의 부모 폴더, 즉 이 저장소 루트다.

```text
bin/drive_talk              프로세스 입구
lib/drive_talk.rb           모듈, 화면 주소표, 나머지 파일 로드
lib/drive_talk/server.rb    HTTP를 읽고 보낸다
lib/drive_talk/store.rb     쿠키 하나로 판을 찾는다
lib/drive_talk/game.rb      화면 이름과 판 값을 바꾼다
lib/drive_talk/deck.rb      질문 10장
lib/drive_talk/view.rb      화면용 계산
views/screen.erb            HTML 원본
public/app.css              가로 기본 모양
public/adaptive.css         세로, 다크
public/app.js               타이머, 마이크
public/fonts/               한글 폰트
BACKEND.md                  나중에 백엔드가 맡을 계약
```

## 입구

`bin/drive_talk`은 세 줄이면 끝난다.

```ruby
require_relative "../lib/drive_talk"
port = Integer(ENV.fetch("PORT", "4567"))
DriveTalk::Server.run(port)
```

`require_relative`는 이 파일 위치 기준으로 찾는다. `require`는 로드 경로를 탄다. 앱 코드는 relative, 표준 라이브러리(`socket`, `erb`, `cgi`)는 `require`다.

`ENV.fetch("PORT", "4567")`는 환경 변수가 없으면 `"4567"`이다. `Integer()`는 `"4567"`을 정수로 바꾸고, `"abc"`면 예외를 낸다. `to_i`는 `"abc"`를 `0`으로 조용히 바꾸므로 여기엔 쓰지 않았다.

## 로드 순서

`lib/drive_talk.rb`가 모듈을 연 다음 다섯 파일을 순서대로 불러온다. `deck`이 `game`보다 먼저인 이유는 `Game`이 `Deck.deal`을 쓰기 때문이다. Ruby는 파일을 위에서 아래로 읽는다. 아직 없는 상수를 그 시점에 부르면 `NameError`다.

`SCREEN_PATH`는 모듈 상수다. `View`와 `Server`는 같은 `DriveTalk` 안에 있으므로 `DriveTalk::` 없이 `SCREEN_PATH`라고 쓴다.

## 요청이 지나가는 파일

```text
server.rb  read_request
    ->  store.rb  쿠키 dt로 Game을 꺼낸다
    ->  game.rb   POST면 상태를 바꾼다
    ->  view.rb   GET이고 주소가 맞으면 HTML
    ->  screen.erb
server.rb  write_response
```

`/assets/`로 시작하면 이 길을 타지 않는다. `public/` 파일을 그대로 보낸다. `..`가 들어 있으면 거절한다. 그게 `asset`의 첫 줄이다.

## 무엇이 화면이고 무엇이 아닌가

`public/app.css`는 화면이다. 값을 바꾸면 새로고침만으로 보인다.

`lib/drive_talk/deck.rb`의 질문 문장도 화면 데이터다. 다만 서버가 켜질 때 읽히므로 고치면 재시작이 필요하다.

`Store`의 `@games`는 공부용 목 세션이다. 해시라서 프로세스를 끄면 비어진다. 여기 데이터베이스를 넣지 않는다. 그 자리는 `BACKEND.md`다.
