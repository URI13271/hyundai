# 이 코드에 나온 Ruby

문법은 이 저장소에 실제로 있는 것만 본다. 터미널에서 따라 치려면 앱 서버와 따로 `ruby -e '...'` 를 쓴다. 한 줄짜리는 서버를 끄지 않아도 된다.

Ruby 3.2 이상을 쓴다. `ruby -v`로 확인한다.

## 심볼과 문자열

`:splash`는 심볼이다. 이름이 값인 꼬리표다. `"splash"`는 글자다.

화면 이름은 심볼이다. HTTP 메서드와 주소는 문자열이다. 브라우저가 보내는 값이 문자열이기 때문이다.

```ruby
case [req[:method], req[:path]]
when ["POST", "/start"] then game.start
end
```

`["POST", "/start"]`처럼 배열도 `when`에 쓸 수 있다. 두 값이 둘 다 같아야 맞는다.

직접 쳐 본다.

```sh
ruby -e 'p :home == "home"; p :home.to_s'
```

`false`와 `"home"`이 나와야 한다.

## 모듈과 클래스

`module DriveTalk`은 이름 공간이다. `class Server`를 그 안에 두면 바깥 이름은 `DriveTalk::Server`다. `::`는 “안의”다.

같은 모듈 안에서는 짧은 이름이 된다. `View`가 `SCREEN_PATH`를 쓸 수 있는 이유다.

## 상수, freeze

`SCREEN_PATH`, `REASON`, `LOCK`은 대문자로 시작한다. Ruby는 이걸 상수로 본다. 다시 넣으면 경고가 나지만 막아주지는 않는다. 그래서 `.freeze`를 붙인다. 얼린 해시에 키를 추가하면 예외가 난다.

```sh
ruby -e 'h = {a: 1}.freeze; h[:b] = 2'
```

`FrozenError`가 나야 한다.

## frozen_string_literal

파일 첫 줄의 `# frozen_string_literal: true`는 그 파일의 문자열 리터럴을 얼린다. `"abc" << "d"`가 실패한다. 실수로 상수를 고치는 일을 줄이려고 모든 파일에 넣었다.

요청 머리글을 모을 때는 일부러 녹인다.

```ruby
head = +""
head << line
```

`+""`는 얼지 않은 빈 문자열이다. `<<`로 이어 붙일 수 있다.

## 메서드

보통 메서드:

```ruby
def hear(choice)
  return unless @screen == :answer && %w[a b].include?(choice.to_s)
  ...
end
```

`return unless`는 조건이 거짓이면 메서드를 끝낸다. 화면이 답이 아니거나 선택이 `a`/`b`가 아니면 아무 일도 하지 않는다. 잘못된 요청을 조용히 무시하는 가드다.

끝이 없는 메서드는 본문이 식 하나일 때 쓴다.

```ruby
def path = SCREEN_PATH.fetch(@game.screen)
def locked? = @game.screen == :read || @fresh
```

`?`로 끝나는 이름은 참/거짓을 돌려준다는 약속이다. 문법 강제는 아니다. `leave?`, `mic?`, `hot?`이 그렇게 쓰인다.

`!`로 끝나는 이름은 위험하거나 자기 자신을 바꾼다는 약속이다. 이 앱에는 없다.

## 키워드 인자

```ruby
def initialize(game, theme:, layout:, demo:)
View.new(game, theme: theme, layout: layout, demo: demo)
```

`theme:`처럼 콜론이 붙은 인자는 순서가 아니라 이름으로 넘긴다. 빼먹으면 `ArgumentError`다. 기본값이 없다.

## 해시

`{ splash: "/", home: "/home" }`는 키가 심볼인 해시다. `req[:method]`는 키가 `:method`인 값을 읽는다.

`fetch`는 키가 없으면 예외거나 두 번째 인자를 준다.

```ruby
req[:cookies].fetch("theme", "system")
```

쿠키가 없으면 `"system"`이다. `[]`만 쓰면 `nil`이 되고, 그 뒤 메서드 호출에서 터질 수 있다.

`SCREEN_PATH.fetch(@game.screen)`는 기본값이 없다. 화면 이름을 잘못 넣으면 바로 실패하게 두었다.

## 배열

`%w[light dark system]`은 `["light", "dark", "system"]`이다. `%i[mic shuffle seats]`는 심볼 배열이다.

```sh
ruby -e 'p %w[a b]; p %i[a b]'
```

`Array(found).first`는 `nil`이면 빈 배열로 보고, 배열이면 그대로 둔 다음 첫 값을 꺼낸다. `nil`에도 `.first`를 부를 수 있게 하려는 것이다.

## 블록, yield

```ruby
Store.with(req[:cookies]["dt"]) do |found|
  game = found
  route(found, req) unless pref_only?(req)
end
```

`do |found| ... end`가 블록이다. `Store.with` 안의 `yield game`이 이 블록을 호출하고, `found`로 판을 넘긴다.

블록은 “이 구간에서만 해 달라”는 뜻으로 쓴다. 여기서는 잠금을 잡은 동안만 판을 만지게 한다. `yield`가 끝나면 `synchronize`가 잠금을 푼다.

`each`도 블록이다.

```ruby
@game.seats.each do |seat|
  ...
end
```

## 참과 거짓

`nil`과 `false`만 거짓이다. `0`, `""`, `[]`은 참이다.

이 한 줄이 이 앱에서 실제로 버그가 됐었다.

```ruby
found = req[:form][key] || req[:query][key]
```

Ruby 3.4의 `CGI.parse`는 없는 키에 `nil`이 아니라 `[]`를 준다. `[]`은 참이라 `||`의 오른쪽, 즉 쿼리 값으로 넘어가지 않았다. `?demo=1`이 무시됐다.

그래서 지금은 비었는지도 본다.

```ruby
found = req[:form][key]
found = req[:query][key] if found.nil? || found.empty?
```

직접 확인한다.

```sh
ruby -e 'require "cgi"; p CGI.parse("")["demo"]'
```

`[]`가 나와야 한다. 이 사실을 기억하면 나중에 폼과 쿼리를 섞을 때 같은 함정을 피한다.

## Data.define

`Deck`과 `Seat`는 클래스 대신 값 객체다.

```ruby
Deck = Data.define(:tag, :title, :a, :b)
Seat = Data.define(:id, :name, :driver)
```

`Deck.new("여행", "여행을 간다면 어디로?", "산", "바다")` 뒤 `card.tag`로 읽는다. 필드를 나중에 바꾸지 않는다. 질문 한 장은 값이므로 이게 맞다.

`def self.deal`은 클래스 메서드다. `Deck.deal`로 부른다. `def deal`이었다면 카드 한 장에만 붙는다.

## 인스턴스 변수와 attr_reader

`@screen`은 그 객체가 요청 사이에 들고 있는 값이다. 지역 변수는 메서드가 끝나면 사라진다. 판이 화면 이름을 기억해야 하므로 인스턴스 변수다.

`attr_reader :id, :screen`은 `def id; @id; end`를 만들어 준다. 바깥에서 읽게는 하되, `screen=` 같은 쓰기는 만들지 않았다. 화면 변경은 `start`, `hear` 같은 메서드만 한다.

## ||= 와 한 번만 읽기

```ruby
def erb
  @erb ||= ERB.new(File.read(...), trim_mode: "-")
end
```

`@erb`가 이미 있으면 그대로 두고, 없으면 오른쪽을 실행해 넣는다. 다만 `View`는 요청마다 새로 만든다. 그래서 템플릿은 요청마다 다시 읽힌다. 캐시가 프로세스 전체에 걸려 있지 않다.

## 문자열 끼워 넣기

```ruby
"A가 #{tally[:a]}장으로 앞섰어요"
```

`#{}` 안은 Ruby 식이다. 결과는 문자열로 붙는다.

쿠키는 주소를 탈출한다.

```ruby
"#{key}=#{CGI.escape(value)}; Path=/; SameSite=Lax"
```

`CGI.escape`를 빼면 값에 `;`가 있을 때 쿠키가 깨진다.

## 정규 표현은 없다

이 앱은 정규 표현으로 라우팅하지 않는다. 주소는 `case`의 문자열 비교다. 화면이 열 개 안쪽이면 이편이 읽기 쉽다.

## 예외

`process`는 이렇게 감싼다.

```ruby
rescue StandardError => e
  warn e.full_message
  write_response(500, ...)
ensure
  @sock.close
end
```

`rescue`는 예외를 잡는다. `ensure`는 성공이든 실패든 실행된다. 소켓을 여기서 닫지 않으면 연결이 남는다.

`StandardError`만 잡는다. `Ctrl-C` 같은 `SignalException`은 일부러 잡지 않는다.

## 오늘 쳐 볼 다섯 줄

서버와 별개로 터미널에서 실행한다.

```sh
ruby -e 'p %i[home seats].include?(:home)'
ruby -e 'p({theme: "dark"}.fetch(:missing, "system"))'
ruby -e 'require "cgi"; p CGI.parse("theme=dark")["theme"]'
ruby -e 'p [nil, false, 0, "", []].map { |v| !!v }'
ruby -v
```

세 번째는 `["dark"]`다. 값이 아니라 배열이다. `param`이 `.first`를 부르는 이유다.
