# 다음 앱

다음에도 Ruby로 화면을 만들 거면, 이 저장소의 파일 역할을 베끼고 게임 규칙은 베끼지 않는다.

## 남길 것

```text
bin/앱이름                 포트만 읽고 Server.run
lib/앱이름.rb              모듈, 주소표, require_relative
lib/앱이름/server.rb       요청을 읽고, 라우트하고, HTML 또는 303
lib/앱이름/store.rb        쿠키로 화면 상태를 찾는다. 필요할 때만
lib/앱이름/view.rb         문장과 class 계산
views/screen.erb           화면 분기
public/app.css             변수로 색을 둔다
```

주소표는 이 형태면 된다.

```ruby
SCREEN_PATH = {
  home: "/",
  detail: "/items"
}.freeze
```

라우트는 이 형태면 된다.

```ruby
case [req[:method], req[:path]]
when ["POST", "/items"] then screen.create(param(req, "name"))
end
```

상태 메서드는 “지금 화면이 맞을 때만”으로 시작한다.

```ruby
def create(name)
  return unless @screen == :home
  return if name.to_s.strip.empty?
  @items << name.strip
  @screen = :detail
end
```

폼은 이렇게 시작한다.

```erb
<form method="post" action="/items">
  <input name="name">
  <button>추가</button>
</form>
```

JS는 타이머나 브라우저 API가 생기기 전에는 넣지 않는다. 넣더라도 `post`처럼 폼 제출로 끝내면 서버의 303을 다시 구현하지 않아도 된다.

## 처음부터 넣지 말 것

- 데이터베이스. 화면 흐름이 안정된 뒤에 붙인다. 계약은 따로 적는다. 이 저장소의 `BACKEND.md`가 그 예다.
- 빌드 도구, npm, CSS 프레임워크. 화면이 하나일 때 이득이 없다.
- 사용자 문장을 그대로 `<%=`에 넣기. `CGI.escapeHTML`이 먼저다.
- 쿼리 값을 그대로 HTML class나 파일 경로에 넣기. 허용 목록을 둔다.
- `sleep`으로 화면 지연. 지연은 `data-delay`와 두 번째 요청으로 만든다.
- 요청마다 스레드를 무한정 늘리는 일을 트래픽이 있는 서비스라고 착각하기. 이 서버는 공부용이다. `connection: close`이고, 스레드 풀이 없고, 잠금 안에서 HTML을 만든다. 사람 몇 명이 한 화면을 보는 용도다.

## 프레임워크로 올라가는 시점

표준 라이브러리만으로 부족해지는 신호가 분명하다.

| 신호 | 그때 볼 것 |
| --- | --- |
| 라우트가 한 화면에 안 들어온다 | Sinatra. `post "/start"` 한 줄이 이 앱의 `case` 한 줄이다 |
| 화면 일부만 바꾸고 싶다 | Hotwire, Turbo. 폼은 그대로 두고 응답만 조각으로 받는다 |
| 계정, 마이그레이션, 메일이 필요해졌다 | Rails. 화면 방식은 여전히 서버가 HTML을 만드는 쪽을 먼저 본다 |
| 브라우저 안에서 상태가 복잡해졌다 | 그때만 클라이언트 프레임워크를 검토한다. Ruby를 브라우저에 넣지는 않는다 |

Opal처럼 Ruby를 자바스크립트로 바꾸는 길은 이 교재의 다음 단계가 아니다. 화면 앱의 주류가 아니고, 이 저장소가 보여 준 요청·리다이렉트·ERB와 다른 기술이다.

Sinatra로 옮길 때도 이 앱의 구분은 유지한다. 라우트는 상태를 바꾸고, 뷰는 문장을 만들고, 템플릿은 그린다. 파일 이름만 프레임워크 관습에 맞추면 된다.

## 새 앱의 첫 날

1. 화면 이름을 다섯 개 이하로 적는다. 주소표부터 만든다.
2. 각 화면의 버튼이 어느 메서드를 부르는지 표를 만든다. `route`의 `when`과 같다.
3. 잘못된 순서의 POST를 무시하는 가드를 먼저 쓴다.
4. 정적 HTML로 한 화면을 만든 뒤 ERB로 값을 끼운다. 반대 순서는 문법과 디자인이 섞여 느려진다.
5. `ruby bin/앱이름`으로 띄우고, `curl -D -`로 303이 맞는지 본다. 브라우저보다 머리글이 정확하다.

## 이 저장소를 베끼기 전에 볼 곳

- 주소와 화면 이름이 다를 수 있다. `SCREEN_PATH`.
- 없는 폼 키는 `[]`다. `param`.
- 문장 메서드는 `View`에 둔다. `score_line`.
- 한 번만 보여 줄 값은 렌더 때 소비한다. `consume_fresh`.
- 재시작이 필요한 파일과 아닌 파일을 구분한다. `docs/study/README.md`의 표.

게임 규칙, 좌석 이름, 10장이라는 숫자는 드라이브 토크 것이다. 다음 앱에 가져가지 않는다.
